# ADR-0012: Auth 소유권과 Compose Exposure Profile Source-of-Truth 분리

## Status

Accepted

Updated to reflect two-mode canonical exposure design: `private_network` + `master_open`, structured diagnostics, single resolver script, and release-gate validators.

## Context

프로젝트에서 auth/env/compose exposure 관리가 여러 파일 사이에서 drift 상태에 있었다:

- `src/ai_model_serving/auth_control.py`의 `AUTH_MODE_EXPECTATIONS` dict가 유일한 auth profile 정의였고, Python 코드 변경 없이는 새 profile을 추가할 수 없었다.
- production/staging의 내부망 Gateway 무인증 운영 패턴이 `local_open`으로 표현되어, `local_open + production` 조합이 auth-doctor에서 FAIL로 처리되는 문제가 있었다.
- Compose host-published port topology가 `ops/compose/full-stack.private-network.yaml`과 `ops/compose/full-stack.example.yaml` 사이에서 정의가 분리되어 있었다.
- `preflight_compose.sh`가 EXPOSURE_MODE와 무관하게 Prometheus, DCGM exporter, cAdvisor, Risk Adapter 포트를 항상 검사했다.
- `AUTH_MODE`가 app-level 인증 정책과 Compose host-published port topology를 혼재해 표현했다.
- env examples에 `embedding-ko-vllm` runtime에 필요한 env key가 누락되어 있었다.
- `bootstrap.sh`가 `private_network`를 "compose default"로 가정해 AUTH_MODE=private_network인 경우 재적용을 생략했다.
- exposure mode가 중간 open modes로 분산되어, full-stack 진단 topology 분리가 "side effect 회피"처럼 설계되어 있었다. 이는 구조적 해결이 아니라 복잡성을 가중시켰다.
- `expected_side_effects`가 free-text 문자열로만 존재하여 preflight/doctor/tests가 구조적으로 판단할 수 없었다.

## Decision

### 책임 분리

`AUTH_MODE`, `EXPOSURE_MODE`, `APP_ENV`의 책임을 명시적으로 분리한다:

- `AUTH_MODE`: app-level 인증 책임만 표현한다 (API key 요구 여부, admin token, internal service token).
- `EXPOSURE_MODE`: Compose host-published port/topology만 표현한다 (어떤 서비스가 host 네트워크에 노출되는지).
- `APP_ENV`: deploy class만 표현한다 (local, staging, production).

### Source-of-truth 파일

- `configs/auth_profiles.yaml`: 모든 AUTH_MODE profile 정의. `auth_control.py`가 런타임에 이 파일에서 `AUTH_MODE_EXPECTATIONS`를 도출한다. Python dict와 YAML이 별개로 존재하지 않는다.
- `configs/exposure_profiles.yaml`: 모든 EXPOSURE_MODE profile 정의. `canonical_modes`, `profiles` (class, diagnostics, host_published)를 포함한다.
- `configs/services.yaml`: host-published service registry. compose service name, host/container port, port env, bind env mapping을 포함한다.
- `configs/env_contract.yaml`: 각 context(profile, exposure mode)에서 필요한 env key 선언. `validate_env_contract.py`가 이를 기반으로 .env example drift를 검사한다.

### 두 가지 canonical exposure mode

exposure mode를 두 가지 canonical mode로 단순화한다:

- `private_network` (class: `default_private`): Gateway와 Grafana만 host-published. 표준 운영 topology.
- `master_open` (class: `diagnostic_full_stack`): 모든 서비스 host-published (vLLM runtimes, Risk Adapter, Prometheus, DCGM exporter, cAdvisor 포함). 진단/운영 full-stack 모드.

**Gateway bypass와 vLLM direct access는 `master_open`의 의도된 특성**이다. 이를 별도 모드로 분리하는 것은 side effect 회피이지 구조적 해결이 아니었다. `master_open`이 전체 stack을 직접 노출하는 것은 정상이며, `EXPOSURE_AUDIENCE`와 structured diagnostics로 제어한다.

### Structured Diagnostics

free-text `expected_side_effects` 대신 구조화된 boolean diagnostics 필드를 사용한다:

- `gateway_bypass_possible`
- `direct_model_runtime_access`
- `direct_risk_adapter_access`
- `direct_operations_endpoints`
- `requires_exposure_audience`

preflight, auth-doctor, exposure-status가 이 필드를 기반으로 판단한다. 문자열 파싱이나 하드코딩이 없다.

### EXPOSURE_AUDIENCE

`master_open` 사용 시 `EXPOSURE_AUDIENCE` 설정이 필수다 (`diagnostics.requires_exposure_audience: true`). 값은 `local_only | private_lan | vpn | public` 중 하나다. preflight이 이를 검증한다.

### internal_trusted profile 추가

`internal_trusted`는 production/staging에서도 허용되는 운영용 무인증 Gateway profile이다:
- `API_KEY_REQUIRED=false` — 인증을 네트워크/호출자에 위임
- `ADMIN_ENDPOINTS_INTERNAL_ONLY=true` — 네트워크 정책으로 admin endpoint 보호 선언
- `FASTAPI_DOCS_ENABLED=false`
- `INTERNAL_SERVICE_AUTH_REQUIRED=false`
- `auth_owner=caller_or_network`

auth-doctor는 `AUTH_MODE=internal_trusted + non-local APP_ENV`를 FAIL이 아닌 `AUTH_DELEGATED_TO_NETWORK` INFO로 표시한다.

### Compose topology 분리

- `ops/compose/full-stack.private-network.yaml`: base/private topology. Gateway와 Grafana만 host-published.
- `ops/compose/overrides/exposure.master-open.yaml`: master_open override (GENERATED by `render_exposure_overrides.py`).

override 파일은 `scripts/compose/render_exposure_overrides.py`가 `configs/exposure_profiles.yaml`과 `configs/services.yaml`에서 생성한다. 수동 편집 금지. drift는 `--check` flag로 검사한다.

`full-stack.example.yaml`은 legacy example 파일로 유지하고 표준 source-of-truth로 사용하지 않는다.

### Single resolver 스크립트

`scripts/compose/resolve_exposure_mode.py`가 EXPOSURE_MODE 라우팅의 단일 authority다:
- canonical mode → pass-through
- unknown mode → stderr error + exit 2

`compose_up.sh`, `preflight_compose.sh`, `setup_env.py`, `exposure_status.py`가 모두 이 스크립트를 사용한다.

### Preflight 개선

`preflight_compose.sh`는 config-first로 동작한다. Phase 0은 Python과
`configs/exposure_profiles.yaml` 로드를 확인한다. Phase 1은 `EXPOSURE_MODE` resolve,
`EXPOSURE_AUDIENCE`, `local_only` bind mismatch, public opt-in을 판단하고 실패 시
Docker/GPU/port/cache/secret 검사를 시작하지 않는다.

Phase 2 host port preflight는 source YAML에서 포트 목록을 다시 만드는 대신 resolver가 정한
base + override file set으로 `docker compose config`를 실행하고 effective
`services.*.ports`만 검사한다. source/override drift는 release gate validator가 맡고,
preflight는 compose가 실제로 바인드할 host port와 bind address를 맡는다. 이미 실행 중인
같은 compose file set의 port만 current stack 소유로 허용한다.

### Service/port registry boundary

service mapping은 `configs/services.yaml`로 분리했다. exposure profile은 어떤 service id를
host-publish할지와 diagnostics만 결정한다. 기존 `configs/ports.yaml`은 제거했고
runtime/document/monitoring port validator도 service registry의 `default_host_port`를 읽는다.

`preflight_compose.sh`는 `.env` 로드와 Python 실행기 선택을 맡는 thin wrapper다.
Phase 0/1/2 exposure decision, effective compose port parsing, diagnostics 출력은
`scripts/compose/preflight_compose.py`가 담당한다.

### Release gate

`release_check.py`의 STATIC_STEPS에 다음이 포함된다:
- `validate_exposure_profiles.py --strict`: canonical_modes ↔ profiles 정합성, compose override 서비스 검증
- `render_exposure_overrides.py --check`: override 파일 drift 검사
- `validate_env_contract.py`: .env example에 required key가 있는지 검사

### Env contract 완성

`.env.example`, `.env.local.example`, `.env.compose.example`에 모든 필수 env key가 있다:
- `embedding-ko-vllm` runtime keys
- bind addr keys (모든 서비스)
- `EXPOSURE_MODE`, `EXPOSURE_AUDIENCE`

## Consequences

| Positive | Negative |
|---|---|
| AUTH_MODE와 EXPOSURE_MODE 책임이 명확히 분리됨 | 기존 테스트 일부 기대값 갱신 필요 |
| internal_trusted로 production 무인증 Gateway 패턴을 명시적으로 표현 가능 | compose override 방식 추가로 운영자 학습 비용 증가 |
| Gateway bypass/direct access가 구조적으로 의도된 것임을 명시 | |
| free-text side effect 대신 structured diagnostics로 preflight/doctor가 판단 | |
| compose override가 자동 생성되어 drift 위험 감소 | |
| single resolver로 모든 스크립트의 mode routing 일관성 보장 | |
| release gate가 exposure/env/override 정합성을 검증 | |
